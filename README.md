# 岗位匹配工作台 0.7.2 · 独立工具与简历工作台捆绑

面向求职者与简历定制客户。Windows 本地工具，无需配置搜索密钥；用户可以在招聘页面自己登录。简历在本机解析，招聘平台只接收已核对的岗位和城市等搜索词。可选 AI 精排另需配置兼容服务，发送内容会先预览。

## 从源码运行

需要自行准备 Node.js 和 Electron 42.4.0。已包含页面运行所需的 vendor 文件；不包含 Electron 安装包、用户数据或任何 AI 凭据。

在项目根目录使用已有 Electron 运行：

```powershell
electron .
electron . --resume-workbench
```

开发测试依赖由 `resume-workbench/package-lock.json` 锁定。需要时在该目录执行 `npm ci`，然后回到根目录：

```powershell
$env:NODE_PATH = (Resolve-Path resume-workbench/node_modules).Path
node --test --test-isolation=none tests/*.test.cjs
Push-Location resume-workbench
node --test --test-isolation=none tests/*.test.cjs
Pop-Location
```

以下“便携版”启动说明面向另行分发的 Windows 包，本源码仓库不包含该二进制包。隐私发布范围见 [PRIVACY.md](PRIVACY.md)。

## 使用

1. 打开 Windows 便携目录中的“打开岗位匹配工作台.cmd”，或双击 job-match.exe。
2. 上传文字 PDF、DOCX、TXT，或粘贴简历；核对目标岗位、城市、学历、已知工作年限、技能、最低月薪。未明确的信息留空。
3. 选择 BOSS、猎聘、智联、前程无忧；拉勾（试读）与实习僧（实习岗位）可按需勾选；可填写最多三个目标公司招聘页，或勾选查找公司招聘官网。点击“查找匹配岗位”。
4. 来源需要登录或验证时，点击该来源“打开来源”，自行处理，再“继续读取”。不会替用户完成验证码或投递。
5. 查看岗位的匹配依据、条件冲突与待确认项，点击“查看岗位 / 投递”，在浏览器中自行投递；也可导出 TXT 岗位清单。

“打开简历工作台.cmd”打开捆绑的原工作台，新增“找匹配岗位”入口。入口把当前稿的职业字段交给独立工具，不传姓名、联系方式、照片、原始全文或私人备注，不改原稿。通过不同入口使用招聘平台时，登录状态可能需要分别建立。不同应用/网页地址的原简历数据请先自行备份后恢复；本包不搬迁原数据。

## 当前范围

- 使用 2026-10-14 客户交付版本留档作为工作台基线，保留批注、交付核对与文本留档。旧正式交付目录未修改。
- 默认每个来源只读取当前渲染页面，最多50条，不自动翻页或批量投递。平台页面变化、登录或验证会影响读取。
- 公司官网支持 JobPosting 结构化数据与可识别的职位详情锚点。任意自定义页面、只有职位编号但无链接的 SPA、特殊登录流程不保证识别。官网发现结果只是候选招聘页，选择并读取后才产生岗位。
- 匹配使用本地规则与文字依据，提供可解释的排序；未开启 AI 时不进行语义分析，分数均不是录用概率。岗位只显示页面提供的信息，未知条件由用户核对。平台详情和仍在招聘状态以投递时为准。
- 文字 PDF/DOCX/TXT 可本地读取；扫描 PDF 不提供 OCR。单文件上限10MB，文字上限20万字符。
- 完整简历不上传到招聘平台，不内置密钥。岗位结果只留当前窗口，关闭前请自行导出清单。招聘登录状态保存在本机当前应用数据目录。
- 纯网页版可读取简历；联网采集须使用 Windows 版。独立源码位于 job-matcher，可用已有 Electron 运行；不要求对最终用户安装 Node/Python。

## 招聘来源扩展（2026-10-15）

- 前程无忧：[当前搜索入口](https://we.51job.com/pc/search)。新版列表的详情地址不在锚点中，工具只读当前公开岗位组件的 jobId 和 jobHref，与 DOM 卡片编号对应后保留原始详情链接及参数。拿不到真实链接时不猜测旧地址。姓名、HR 和账号字段不在读取范围。
- 城市映射含 197 个前程无忧官方字典条目，来自页面引用的[官方城市字典](https://fecdn.51jobcdn.com/fe/static/51job/2026/01/21/942631f516198b042/seo_dd_areas.js)，保存为 51job-city-codes.json。未知或未填城市使用平台默认搜索范围，可在来源页手动调整。
- 实习僧：[当前实习搜索入口](https://www.shixiseng.com/interns)。读取当前卡片的岗位、公司、城市和原始详情链接。特殊字体导致的不可读薪资留空并提示核对；日薪不直接和月薪比较，不把每周实习天数当工作年限。
- 拉勾：[当前搜索入口](https://www.lagou.com/wn/jobs)。本次未登录访问要求滑块验证。提供兼容提取逻辑和继续读取入口，登录/验证后的真实岗位读取尚未验收，因此标为“试读”，默认不勾选。
- 实习僧默认不勾选，避免将实习岗位混入常规社招；前程无忧与原有三个通用来源默认勾选。均可自行调整。

## 开发验证

无新增依赖。测试使用原项目已安装的 jsdom/fake-indexeddb。`node --test tests/*.test.cjs` 测新工具，进入 `resume-workbench` 目录后运行 `node --test tests/*.test.cjs` 测原工作台；需按本机路径设置 NODE_PATH。便携包复用已有 Electron 42.4.0，保留许可证。

核心初稿与测试由用户指定的 Hermes（现有火山 Coding Plan / GLM-5.3 Flash 配置）编写，Codex 完成集成、问题修正、独立验证和打包。真实招聘平台的已验证/未验证情况见正式交付目录中的验收记录；自动测试不等于客户使用或商业验证。

## 可选 AI 精排与校招来源（0.7.1）

学历低一个层级、工作经验少不超过 2 年时保留岗位并提示差距；差距更大才默认隐藏，仍可展开查看。

岗位清单上方勾选“AI 精排”，填写兼容 Chat Completions 接口的服务地址、模型名和 API 密钥。本机回环服务可无密钥（需要你已有可运行的模型服务，不随本包安装）。先预览，再点击发送；每次分析规则筛选后的前 10 个候选，显示匹配点、差距、待核对信息和可核对原文。调用失败或关闭 AI 时继续使用本地规则。手动设置与密钥仅保留当前窗口；“使用本机 AI 服务”会在用户主动点击后读取受支持的本机配置，详见下文。

卡片中可补充完整岗位要求；只读取到摘要时会提示信息不足。职业信息和岗位文本将发给你填写的服务，云端服务可能计费。独立身份/联系字段排除，文本做基础脱敏，发送前仍请检查预览。不要将 AI 分数视为录用概率。

新增国家大学生就业服务平台：已实测全国关键词搜索、当前页读取和原始岗位详情。新增应届生求职网试读入口：搜索要求登录，登录后读取尚待验证；首页推荐不会作为搜索结果。具体测试及 GitHub 对标见《AI精排与校招来源验收.md》。

## 0.7.1 真实 DeepSeek 验证

勾选 AI 精排后，可点“使用本机 DeepSeek”：优先读取现有 Hermes .env 中的 DEEPSEEK_API_KEY，再回退同名环境变量。密钥仅在主进程内存使用，不回传页面、不另存；仅可用于 DeepSeek 官方 HTTPS 接口。仍需预览并点击发送才调用。关闭窗口后需重新点击此入口。

DeepSeek 默认思考已关闭，避免输出额度耗尽却无评分；输出截断明确报错，不自动重试。职业数据增加教育专业及毕业日期；未知信息与明确差距分别提示。2026-10-15 使用虚构简历与真实国家大学生就业服务平台岗位完成一次成功闭环，详见正式交付根目录《真实AI全流程验收.md》。本轮未重新验证所有招聘平台。

## 0.7.2 BOSS 与前程无忧实测

修复 BOSS 岗位原文中康熙部首兼容字符导致的引文误拒绝，只统一 U+2F00–U+2FD5，不做模糊匹配、繁简转换或文字删改。2026-10-15 两站各完成10条详情正文的真实 DeepSeek 精排并打开首位岗位链接；本轮由测试脚本读取详情后填入已有补充要求栏，并未新增产品自动抓取完整 JD 的按钮。BOSS 模型输出仍可能把未提供信息误归为差距，需人工核对。
