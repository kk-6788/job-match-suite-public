# 简历工作台 2.1

面向个人求职、简历定制接单的本地工作台。Windows EXE 和网页版共享同一套编辑、导入、质量检查与导出功能。

## 2.1 改进

- 版式选择显示13 套模板的真实示意缩略图，右侧仍预览自己的内容。
- 每个教育、工作、项目、技能、证书条目支持上下移动，保留修改前历史，可恢复。
- 简历标题右侧菜单新增“为新岗位创建副本”：填写新岗位和 JD，保留原稿，新副本重新核对与评分。
- 导出窗口新增“核对 / 导出纯文字”，可复制或下载 UTF-8 TXT，按显示顺序输出可见内容，不包含原材料、私人备注、JD 或照片。该视图不是 PDF 解析或第三方 ATS 认证。

参考来源与取舍见 [GitHub 参考记录](docs/github-reference-upgrade.md)。

## 直接使用

### 本地导入修复（2026-09-29）

2026-09-30 补充：无栏目标题的整段文字可按常见自我介绍、称呼、任职日期、单位、岗位和职责写法识别，不必先整理成标准简历。称呼会提示核对真实姓名；历史岗位与目标岗位分开，未提供的信息留空。规则仍需人工核对，不保证理解任意自由叙述。待核对字段改用中文名称。

补充修复：支持浮动文本框 Word 简历按分栏和位置恢复阅读顺序，识别“教育背景 Education”等中英双语标题，并将侧栏学历与对应学校合并。避免把正文软换行、编号段落误判成新栏目或经历名称。对缺少明确单位/岗位的材料保留描述，不自动补造；占位词和疑似编辑残留提示核对。

导入默认使用本地解析，不需要 AI、API Key 或联网。文字 PDF、DOCX 和粘贴文字支持基本信息、教育、工作/实习、项目、技能、证书及个人简介；兼容常见标题、空格/分隔符和分行日期。技能详细内容和完整原文保留，导入前可核对、修改，再创建新简历。

无法确定的字段会提示核对。扫描 PDF、图片仍需 OCR 或图片 AI；本次未增加本地 OCR。复杂多栏 PDF 的阅读顺序可能仍需人工调整，不能保证任意版式均准确归类。

- Windows：解压完整便携目录，双击 `简历工作台.exe`。无需安装 Node.js/Python；不要只移动 EXE。
- 网页版：双击 `index.html`，使用 Chrome/Edge。基础编辑、PDF/DOCX 本地读取、Word/图片导出不需要 API Key。
- 如果网页直连 AI 被服务商跨域策略限制，请使用 Windows 版。手机浏览器支持编辑；没有云同步。

## 建议工作流程

1. 新建简历，或导入 PDF、DOCX、截图、粘贴文字。
2. 对照原材料核对提取结果。确认后新建简历，不覆盖已有客户资料。
3. 填写目标岗位，粘贴 JD，点击“找出材料缺口”，回答最多 5 个关键问题。答案保存在补充材料中；需要新增数字时先将已核实的事实填入对应经历，再润色。
4. 运行整份或单条润色，逐项对比、勾选确认后应用。AI 新增原文没有的数字会被拒绝。
5. 在“排版”中选择 13 种版式，调整模块顺序、隐藏、配色、字号、间距。默认尽量一页，文字最小 10pt；内容过多时提示精简并完整分页。
6. 核对事实、勾选真实性确认，运行完整质量检查。查看每条扣分的原因、原文依据和改法。
7. 导出 PDF、可编辑 Word 或自定义水印预览图。未达标仍可导出当前稿，但不会被标记为达标交付。

## 85 分标准

| 维度 | 分数 | 检查方式 |
|---|---:|---|
| 岗位匹配 | 25 | 5 项 AI 证据审查 |
| 经历与贡献 | 25 | 5 项 AI 证据审查，不强求量化 |
| 信息完整与一致 | 20 | 本地检查姓名、联系、岗位、教育、经历、年月及占位符 |
| 表达质量 | 15 | 3 项 AI 证据审查 |
| 排版与可读性 | 15 | 实际页面文字、溢出和预计页数 |

内容项每项通过得 5 分、部分通过 2.5 分、未通过 0 分；程序加总后四舍五入。**总分至少 85，且没有必须修正的问题，已提供 JD 并确认真实性，才标记交付达标。**

没有有效 AI 审查时只显示本地部分分数，绝不伪造总分。内容、JD、补充材料、模块顺序或显示变化会让旧审查失效。重启/恢复备份后需重新审查。分数是工作台内部质量门槛，不是录用概率；主观审查仍可能存在模型偏差。

## 保存、历史与备份

- 左侧每份简历卡片均有“删除”按钮；确认框显示对应简历名称，取消不会删除。删除最后一份时会新建空白简历；删除也会移除该份简历的历史版本。

- 数据优先保存在 IndexedDB，不可用时回退本地存储。新版会尝试读取同一浏览器中旧版 `resumeProDataV1` 数据，保留旧数据。
- 每份简历保留最近 **5 个修改前快照**。点击“历史版本”恢复时，也会保留恢复前的稿件。
- 可搜索、复制多份简历。备份导出 JSON，包含材料、布局和历史，**不包含 API Key**。恢复以新 ID 加入，避免覆盖现有简历。
- EXE、不同浏览器和不同网页地址分别保存数据。换环境前先备份；清除浏览器数据会删除本地记录。
- 多窗口保存发生冲突时停止覆盖并提示备份；请备份当前稿，再刷新读取另一个窗口的版本。桌面版限制为一个主实例。

## AI 配置

打开“AI 设置”，选择 DeepSeek、Agnes 或自定义 OpenAI 兼容服务。用户填写自己的 Base URL、模型和 Key，可获取模型列表并测试连接。图片识别可单独指定支持图片输入的模型。

详见 [AI 配置说明](docs/ai-setup.md)。免费额度和计费以服务商账户为准，程序不承诺无限免费。程序不内置个人密钥、不自动读取旧代理的外部配置。

Windows 记住密钥使用系统加密；网页勾选记住后保存在当前浏览器，不是系统级加密。可不勾选，仅在当前会话使用。备份和分发包中不包含密钥。

## 已知边界

- 扫描型 PDF 没有可选文字时，需要先转为图片再识别；旧 `.doc` 请另存 `.docx`。
- 本地规则解析适合明确标题和分隔符，复杂多栏材料建议 AI 识别并人工核对。AI 结果必须能在原文定位，否则留空标记。
- Word 保留可编辑文本、模块顺序、隐藏状态、配色和有效字号；不承诺与 7 种 PDF 视觉版式逐像素相同。Word 的分页还受本机字体和软件版本影响，交付前需打开核对。
- 预览中的多页数量是估计值，实际 PDF 因段落分页规则可能不同；内容不会为了页数被裁切。
- 没有登录、支付、云同步。发布 EXE 未做代码签名，不自动安装系统组件。

## 开发和构建

需要 Node.js 20+、Windows PowerShell。前端是普通 HTML/CSS/JavaScript，无需开发服务器即可使用。

```powershell
npm ci
npm test
npm run vendor
npm run preview
```

本机预览只暴露 `index.html` 与 `app/`、`vendor/` 的 JS/CSS，不暴露根目录客户文件。

```powershell
# Electron 42.4.0 Windows x64 官方运行包存在缓存时
npm run build
# 或指定已下载的官方 ZIP
$env:RESUME_ELECTRON_ZIP = (Join-Path $env:USERPROFILE 'Downloads\electron-v42.4.0-win32-x64.zip')
npm run build
```

构建输出 `outputs/简历工作台-2.1-Windows`；存在旧目录时不会直接覆盖。只白名单打包应用代码和运行依赖，排除历史客户文件。

代码模块：`core.js` 管数据与评分，`app.js` 管交互，`render.js`/`resume.css` 管预览，`ai.js` 管 AI，`services.js` 管文件，`desktop/` 管隔离的 Electron 外壳。

## 客户诊断与改稿交付（2026-10-13）

编辑页新增“客户交付”：修改前先保存对照原稿，完成岗位定制与质量检查后，保存人工改稿说明，预览并核对后导出离线 HTML / TXT 报告。报告含当前问题、可见栏目改前改后对照及人工说明，默认不取姓名、联系方式、照片、私人材料或完整 JD。手写说明及经历正文仍需人工核对，不自动去除其中所有敏感信息。

无有效审查时不显示总分；稿件修改会使旧说明过期，报告不展示过期说明。备份与历史保留新字段，恢复备份仍需重新审查。报告预览后内容若变化，必须重新预览与确认。HTML 可用浏览器打印另存 PDF。

本次更新的是源代码与网页版，原有便携 EXE 未重新打包。导入不同目录的网页时，如需已有资料，请自行在旧入口导出备份，再在新入口恢复；不用客户资料验证新版。功能完成不等于已有客户愿意付费。

## 逐栏目改稿说明与客户反馈（2026-10-14）

客户交付页在有差异的栏目旁新增人工理由、依据、客户状态及反馈原文。明确保存后才进入报告；稿件、原稿或版式改变后，旧记录保留作待核对草稿，但不会自动进入新版报告。待客户确认、人工记录客户已确认、需返工分别显示，不作为质量审查或事实认证。原因与反馈各限1500字，历史及v2备份保留新字段。预览后的说明与反馈变更沿用重新预览确认保护。

新增界面和HTML/TXT报告为本地操作，不新增模型请求。旧便携EXE未重新打包，请用升级后的 index.html。真实客户付费及收入尚未验证。

## 交付前核对与客户待补信息（2026-10-14）

客户交付页新增实时核对有效审查、内部质量门槛、原稿、说明、客户反馈五项条件。已记录的待确认、返工或陈旧说明不会被高分覆盖；状态由当前稿派生，不写入备份当作认证。仍允许预览和导出诊断草稿，不代表客户验收。

诊断报告标明具体栏目、条目和字段；缺少日期按起止年月描述。报告预览中可展开客户待补信息清单，核对后下载TXT。清单只列客户需补充/确认事项，内部审查与保存原稿等事项留在工作台。预览后数据变动需重新预览和确认，下载采用已预览文本；操作本地完成，无新模型请求或依赖。


## 客户核对版 TXT 留档（2026-10-14）

客户报告预览中填写留档标签，查看报告与待补清单、勾选人工核对后，点击“留档报告文本”。客户交付页底部可查看和重新下载当时的诊断 TXT 与待补清单 TXT。后续编辑、恢复编辑历史都不改动旧档；复制简历或岗位副本不携带别人的交付留档。

每份简历最多留5份，不自动淘汰；重复文本拒绝保存；删除需再次确认。单份每段文本最多400000字符，单份简历全部留档合计最多1000000字符。存储失败明确报错，不能当作已留档。备份包含留档，旧v2备份仍兼容；损坏留档拒绝整批恢复。留档默认留在本机，只保存人工核对的文本，不含简历快照或配置。手写内容仍需核对隐私。

此功能只留档报告与清单TXT，不保存HTML、PDF、Word或发给客户的附件，不自动发送、不记录客户验收，也不保证收入。请另外保留实际发送附件，并定期备份本机资料。旧便携EXE未重新打包。
